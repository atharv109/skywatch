## Decisions recorded

1. **Bundle broadcast relevance radius = 5 km** (`MESH_MSG_BUNDLE_RADIUS_KM`): the spec said "relevant to the gateway's area" without a number; 150 m (corroboration) is too tight for chat, the whole mesh defeats the point. Direct-to-gateway msgs ride regardless of distance.
2. **/mesh/state `messages` is global, unfiltered, all verify states**: the endpoint is open-read and identity-less (no viewer to auth a DM check against); `to` exposes the routing so node pages can filter client-side (they know their own hash). A sig-failed msg still rides (transport, consistent with "never dropped silently") — demo-grade, ledgered.
3. **`to` validated loosely** (string 1..128): it originates client-side; the backend does not enforce a 10-hex shape or that it hashes to a known device.
4. **`displayedStatus` mirrored, not imported**: mesh/state.ts must not depend back on map/state.ts (landed comment says so); cross-ref comments at both sites follow the established 911-string mirror pattern.
5. **Resources on the mesh section = ALL ResourceDocs** (shelters + pharmacies + community centers), same as /map/state — kind rides in the view so consumers can filter to shelters.
6. **Bundle message sort by device `ts`** (newest first), matching the state `messages` order; device-clock skew is accepted everywhere else in mesh too.

## Parks / carries
