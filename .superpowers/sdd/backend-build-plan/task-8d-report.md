## Decisions recorded

1. **Context = the ASKER's packet coordinates** (controller correction mid-task): the stranded user answers from their own loc; the gateway's lat/lon is only the returned bundle's broadcast anchor. Implemented in `makeSkywatchChat` (point-brief from `question.loc`) — no gateway involvement in the answer at all.
2. **verify "core" as the server-author exemption** (coordinator's sketch): no per-boot server keypair — the server IS the author, so a sig would be theater. Never clustered (also structurally impossible: msg type has rescueKind null), never scored/decayed, always delivered (state messages + bundle ignore verify for msgs).
3. **Answer addressing = direct to the asker's hash, always** (the question was addressed to the responders' node). It rides the bundle of the gateway whose hash equals the asker's (asker-is-gateway) and is always visible in the /mesh/state thread — the phone page's chat surface. No broadcast-answer mode (not in the spec beyond the "normal radius rules" phrase; noted for the frontend).
4. **Questions are answered regardless of sig state** — consistent with msg transport ("never dropped silently"); answering a spoofed question wastes demo-scale Gemini quota, ledgered as acceptable.
5. **Answer text sliced to the packet cap (280)** — chat's own bound is 300; slice happens at storage, after validation (validator correctness untouched; a 281-300 char valid answer truncates — acceptable transport trim, documented).
6. **Reserved-id rejection is parse-level** ("rejected, id echoed") — it is the cheapest airtight guard against TOFU identity theft of the trusted core.
